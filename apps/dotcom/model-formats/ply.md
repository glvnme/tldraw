## The format, briefly

Greg Turk's Polygon File Format (1994). A text header declares elements and their properties, then the body holds the data in ASCII or binary:

```
ply
format binary_little_endian 1.0
element vertex 8
property float x
property float y
property float z
property uchar red
property uchar green
property uchar blue
element face 6
property list uchar int vertex_indices
end_header
```

Used for scans and photogrammetry meshes. It has no units, no object identity and no hierarchy. A PLY with vertices and no faces is a point cloud, and 3D Gaussian splat PLYs carry extra properties (`f_dc_*`, `opacity`, `scale_*`).

## Dependency and licence

None.

## Conversion steps

1. Parse the header lines up to `end_header`, recording elements with counts and typed properties (`char`/`int8` … `double`/`float64`, and `list <countType> <itemType>`). Unknown elements and properties are skipped, using their sizes in binary.
2. Read `vertex`: `x y z`, plus optional `nx ny nz`, `red green blue [alpha]` (uchar or float), and `s t`/`u v`.
3. Read `face` (`vertex_indices` or `vertex_index`): fan-triangulate polygons. Check that indices are in range.
4. **No faces:** throw `no_geometry` with "This PLY is a point cloud". Point clouds and splats need a point renderer and are out of scope. If the header has `f_dc_0`, say "Gaussian splat" instead.
5. **Vertex colours:** the current `GlbScene` has one material per mesh. Either quantise colours into up to 64 materials, or (preferred, small change) add an optional `COLOR_0` attribute to `GlbMesh` and `writeGlb`. gltfpack keeps `COLOR_0`.
6. **One feature** for the whole file: `sourceId` = `file-local` `'mesh'`, `name` = filename.
7. **Units:** none in the file. Assume metres for scans (most scan tools write metres) and warn `units_assumed`. Let the user override.
8. **Axes:** assume Y-up for scan tools, which is unverified per tool. Let the user override, as with OBJ.

The ghost reference takes `authoring` from `comment` or `obj_info` lines when present (for example `comment generated by …`).

## Estimate

About 300 lines and 2 to 3 days.

## Tests

ASCII and both binary endiannesses; quads and n-gons; vertex colours as uchar and as float; a point-only file (`no_geometry`); a truncated binary body (`conversion_failed`).

## Instructions for users

Export PLY with faces (a mesh, not a point cloud) from the scan or photogrammetry tool, decimated to a few million triangles. For textured scans, export GLB or OBJ, which keep the texture coordinates.
